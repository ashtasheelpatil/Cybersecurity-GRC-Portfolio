# Risk Register

## Purpose
The Risk Register records identified information security risks and provides a structured basis for risk evaluation and treatment.

## Methodology
This portfolio uses a qualitative **5 × 5 risk matrix**:

**Risk Score = Likelihood × Impact**

### Likelihood
1 = Rare  
2 = Unlikely  
3 = Possible  
4 = Likely  
5 = Almost Certain

### Impact
1 = Insignificant  
2 = Minor  
3 = Moderate  
4 = Major  
5 = Severe

### Rating
- 1–4 = Low
- 5–9 = Medium
- 10–16 = High
- 17–25 = Critical

## Risk Lifecycle
1. Identify the asset/process.
2. Describe the risk scenario.
3. Identify the threat.
4. Identify the vulnerability or weakness.
5. Record existing controls.
6. Assess control effectiveness.
7. Calculate inherent risk.
8. Assign a risk owner.
9. Select a treatment decision.
10. Define treatment action.
11. Calculate residual risk.
12. Track status and evidence.

## Initial Risk Register
The simulated register contains **12 risk scenarios** covering:
- Customer information
- Source code
- AWS cloud
- SaaS application
- Identity and access management
- Endpoints
- Backups
- Security monitoring
- Remote access
- CI/CD
- Microsoft 365
- Customer contracts

## Important Portfolio Rule
These risks and scores are simulated for demonstration. In a real assessment, likelihood, impact, control effectiveness, treatment, and acceptance decisions must be validated with appropriate asset/business owners.
