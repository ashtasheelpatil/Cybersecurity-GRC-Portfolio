# Corrective Action Register

## Purpose
The Corrective Action Register converts simulated audit findings from the Audit Evidence Register into tracked corrective actions.

## Corrective Action Lifecycle

**Finding → Correction → Root Cause → Corrective Action → Evidence → Effectiveness Check → Closure**

## Contents
The register contains 10 corrective actions covering the most important simulated audit gaps:
- MFA coverage
- Source-code access review
- Cloud configuration monitoring
- Backup restore testing
- Log review
- Security monitoring
- Security awareness
- Secure-development testing
- Environment privilege review
- Privileged-access certification

## Why This Matters for GRC
A GRC professional must not stop at identifying a nonconformity. The organization needs to:
1. Correct the immediate issue.
2. Understand the root cause.
3. Implement systemic corrective action.
4. Collect objective evidence.
5. Verify effectiveness.
6. Formally close the action.

## Important
All findings, root causes, actions, owners, dates, and verification results are simulated for this portfolio project.
